# M1a — Storage on SQLite and PostgreSQL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend-neutral repository traits with complete SQLite and PostgreSQL implementations of the M1 schema, reversible expand/contract migrations with a startup compatibility check, and one contract test suite that proves both backends behave identically.

**Architecture:** `ferrite-domain` holds pure types. `ferrite-store` defines `Store`/`Tx`/`Repos` traits (async-trait, trait objects), `StoreError`, and backend-neutral migration logic (directive parsing, compatibility verdict). `ferrite-store-sqlite` and `ferrite-store-postgres` each implement every repo with runtime-checked `sqlx` queries and embed their own migrations. `ferrite-store-tests` runs every contract test against both backends.

**Tech Stack:** Rust 1.98, edition 2024; sqlx 0.9 (`runtime-tokio`, `tls-rustls`, `sqlite`, `postgres`, `migrate`, `macros`, `json`, `uuid`, `chrono`; no default features); uuid 1 (v7, serde); chrono 0.4 (serde); serde/serde_json; async-trait; thiserror; tracing; base64 0.23 (cursors); tempfile (tests).

**Spec:** `docs/design/02-storage.md` (primary), `docs/design/00-overview.md` (D8, D9, D15), `docs/design/04-cluster.md` §4 (events outbox shape), `docs/design/10-testing.md`.

## Global Constraints

- Errors: `thiserror` in libraries; no `anyhow` outside binaries/tests. No `#[allow(dead_code)]`; no `unwrap`/`expect` in non-test code (workspace lints warn; clippy `-D warnings`).
- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` pass. Existing M0 crates and plugin tests must keep passing.
- D9: **runtime** `sqlx::query`/`query_as`/`query_scalar` only — no `query!` macros. `sqlx::migrate!()` macro for embedding migrations is allowed.
- D15: ids are UUIDv7 (`Uuid::now_v7()`), created in Rust before insert.
- Physical types (02 §5): id → SQLite `BLOB` / PG `uuid`; timestamp → SQLite `INTEGER` **unix microseconds UTC** / PG `timestamptz`; json → SQLite `TEXT` / PG `jsonb`; bool → SQLite `INTEGER` 0/1 / PG `boolean`; bytes → `BLOB` / `bytea`; case-insensitive unique text → SQLite `COLLATE NOCASE` / PG unique index on `lower(col)`; autoincrement → SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` / PG `bigint GENERATED ALWAYS AS IDENTITY`.
- Migrations: `crates/ferrite-store-sqlite/migrations/` and `crates/ferrite-store-postgres/migrations/`; sqlx reversible naming `NNNN_name.up.sql` / `NNNN_name.down.sql`; 4-digit sequential versions; **identical version numbers and names on both backends**; every migration has a `.down.sql`.
- Directives (02 §7), first comment lines of an `.up.sql`: `-- ferrite:phase expand|contract` (default expand), `-- ferrite:min-binary X.Y.Z` (contract only), `-- ferrite:lossy-down`.
- SQLite connection (02 §6): `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000` ms, `temp_store=MEMORY`; **writer pool max 1 connection**, reader pool N (default 4); all `Tx` use the writer; data-folder lock file `ferrite.lock` held for the process lifetime via `std::fs::File::try_lock()` (stable since Rust 1.89).
- PostgreSQL connection: one pool, `max_connections` default 16, `statement_timeout = 30s` on app connections, optional `schema` (sets `search_path`).
- SQLite pre-migration snapshot: `VACUUM INTO 'data/backups/pre-<from>-to-<to>-<UTC yyyymmddThhmmssZ>.db'`, keep the newest 5.
- Postgres tests: env `FERRITE_TEST_PG_URL`; locally unset → Postgres tests print a `SKIP` line to stderr and return early; when `CI=true` and unset → panic. One schema per test (`t_<uuid simple>`), dropped at the end.
- Revision retention default: 50 per item.
- Pagination: cursor-based, `limit` ≤ 200, cursor = URL-safe base64 (no padding) of JSON `[sort_key, id]`.

### Verified API facts (spike on 2026-10-22, sqlx 0.9.0, local PG 17)

- `static M: Migrator = sqlx::migrate!("./migrations");` embeds reversible `.up.sql`/`.down.sql` pairs; `M.run(&pool).await`, `M.undo(&pool, target_version).await` (target 0 = undo all); `M.iter()` yields `Migration` with `version`, `description`, `migration_type.is_reversible()`.
- `SqliteConnectOptions::new().filename(p).create_if_missing(true).journal_mode(SqliteJournalMode::Wal).foreign_keys(true)`, `SqlitePoolOptions::new().max_connections(1).connect_with(o)`.
- Binding `uuid::Uuid` on SQLite stores a 16-byte BLOB and reads back equal; `chrono::DateTime<Utc>` binds to PG `timestamptz`; `sqlx::types::Json<T>` binds on both.
- Local Postgres for development: `postgres://ferrite@localhost:54329/ferrite_test` (trust auth; started by the controller from `/opt/homebrew/opt/postgresql@17/bin`).

## Review Focus

1. **Concurrent writers on SQLite** (8 tasks each committing 50 small transactions) → all commit, no `SQLITE_BUSY` surfaces as an error. *Test in Task 4.*
2. **Optimistic-lock race**: two updates of the same item with the same expected `version` → exactly one succeeds, the other gets `StoreError::Conflict` carrying the current version. *Test in Task 5.*
3. **Slug uniqueness with NULL parent** (two top-level pages with the same slug) → second insert fails with `StoreError::UniqueViolation { constraint }` on both backends (Postgres treats NULLs as distinct unless handled; SQLite too). *Test in Task 5.*
4. **Dropped transaction** (a `Tx` dropped without commit/rollback) → changes are not visible and the writer connection is usable again. *Test in Task 4.*
5. **Unicode/case** in slugs, logins and e-mails (`Ünïcode`, `USER@Example.com` vs `user@example.com`) → e-mail uniqueness is case-insensitive on both backends; slugs are stored exactly as given. *Test in Task 7.*

pub enum Backend { Sqlite, Postgres }
#[derive(thiserror::Error)] pub enum StoreError {
    NotFound, Conflict { current_version: i64 }, UniqueViolation { constraint: String },
    ForeignKey { constraint: String }, Invalid(String), Unsupported(&'static str),
    Migration(String), Incompatible(String), Database(String) }
#[async_trait] pub trait Store: Send + Sync + 'static {
    fn backend(&self) -> Backend;
    fn read(&self) -> &dyn Repos;
    async fn begin(&self) -> Result<Box<dyn Tx>, StoreError>;
    async fn migration_status(&self, binary: &semver::Version) -> Result<MigrationStatus, StoreError>;
    async fn migrate_up(&self, to: Option<i64>) -> Result<Vec<i64>, StoreError>;          // applied versions

    async fn snapshot(&self, dest: &std::path::Path) -> Result<(), StoreError>;            // Postgres → Unsupported
