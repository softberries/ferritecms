# M1c-2 — Serving: Router, Themes, Page Cache, Plugin Wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ferrite serve --data DIR` serves a real site: permalinks and redirects, a MiniJinja theme with the WordPress-style hierarchy, the `blog` starter theme, plugin `render.head` / `content.body` / `content.excerpt` filters from installed plugins, a dependency-indexed page cache invalidated by outbox events, `/_media` and `/_theme` assets, feeds, sitemap and robots — identical on SQLite + local media and Postgres + S3.

**Architecture:** New crates `ferrite-theme` (theme loading, hierarchy resolution, MiniJinja environment, safe helpers), `ferrite-cache` (page cache + dependency index), `ferrite-http` (axum app, router, handlers). `ferrite-core` gains a public read facade (`SiteReader`), a permalink module and the dependency-key contract. The binary gains `serve` and `seed demo`. Rendering: route → `SiteReader` loads a fully-populated `PageData` (batch loaders, published-only) → plugin filters → theme render on a blocking thread → cache store with recorded keys.

**Tech Stack:** axum 0.8 (path params `/{name}`), tokio, tower-http 0.7 (compression, trace), minijinja 3.0 (features `fuel`, `loader` not needed — custom loader), moka 0.12 (`future` cache, weigher), rust-embed 8.13, httpdate 1.0, existing workspace crates.

**Spec:** `docs/design/06-themes-rendering.md`, `docs/design/01-architecture.md` §2–§3, `docs/design/05-plugin-host.md` §4/§7/§7a, `docs/design/03-media.md` §5, `docs/design/04-cluster.md` §4 (event kinds). Prior rulings: `docs/superpowers/rulings/m1a.md`, `m1b.md`, `m1c1.md` (R9 assigns the first three tasks below).

## Global Constraints

- All earlier rulings stay binding (store parity, P1 no store.read()/begin() inside a Tx, Tx poisoning, validation of caller text, COLLATE "C").
- `thiserror` in libraries, `anyhow` only in `crates/ferrite`; no `unwrap`/`expect` in non-test code; no `#[allow(dead_code)]`; fmt + clippy `-D warnings`; `CI=true FERRITE_TEST_PG_URL=postgres://ferrite@localhost:54329/ferrite_test cargo test --workspace` passes; HTTP integration tests run on **both** profiles (SQLite + local media; Postgres + in-process S3).
- **Public reads are published-only by construction** (M1c-1 R9/I4): the HTTP layer never builds a raw `ContentQuery`/`SearchQuery`; it calls `SiteReader`, which forces `statuses = [Published]` and `published_at <= now`. Drafts are reachable only via `preview(actor, id)` (gated by `can_edit`), never cached.
- **Dependency-key contract** (`ferrite-core/src/events.rs` doc, settled in Task 3): content writes (update and every lifecycle transition) emit `post:<id>`, `archive:<kind>`, `term:<id>` for the union of old and new terms, and `post:<old parent>`/`post:<new parent>` when relevant; the renderer records `post:<id>` for **every** item it shows (single item, each listed item, menu targets), `term:<id>` for every term shown, `archive:<kind>` for listings, `menu:<name>` for menus, `option:<key>` for options read, `theme` and `plugins` for every page. Redirect writes emit `invalidate` with key `redirect:<source>` (and toggled variant); the router checks redirects **before** the cache, so redirect events are informational in solo mode.
- Permalink structures (06 §3): post default `/%slug%/`, page `/%parent_path%/%slug%/` (ancestor slugs), other public types `/{type}/%slug%/`; option `permalink.post` may be `/%year%/%month%/%slug%/` or `/%category%/%slug%/`. Trailing slash canonical; the non-canonical variant 301s to canonical. Paths percent-encode slug segments.
- Cache: key = (host, path, sorted allowlisted query params `page`, variant); variant `anon` only in M1c-2 (logged-in bypass; there is no login yet). Max bytes from `cache.max_bytes`. Not cached: non-GET/HEAD, 4xx/5xx, previews, responses with `Set-Cookie`. Search results cached 60 s TTL. Volatile pages (plugin kv/http/clock use, 05 §7a) TTL 60 s.
- `/_media/{hash}/{name}`: streaming via `MediaStore::open_read`, Range → 206 / 416, `ETag: "<hash>"`, `Cache-Control: public, max-age=31536000, immutable`, `X-Content-Type-Options: nosniff`; `inline_safe(mime)` → inline with that type, PDF additionally `Content-Security-Policy: sandbox`; everything else `application/octet-stream` + `Content-Disposition: attachment`. Only artifacts referenced by a published media item (or a variant of one) are served (404 otherwise).
- Security headers on HTML: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`.
- Theme templates: no filesystem/network access, loader limited to the theme's files, MiniJinja `fuel` enabled (limit 5 000 000 per render), auto-escape for `.html`/`.xml`. Template errors in production → 500 using theme `500.html` or a built-in page; never cached.
- **Plan ruling P1:** theme distribution via artifacts is M1.5; M1c-2 loads themes from (a) embedded starter themes (`rust-embed`) and (b) `data/themes/<name>/` folders. The `themes` table records the active theme name; default `blog`.
- **Plan ruling P2:** MiniJinja is synchronous, so all data a template may use is preloaded into `PageData` before rendering; the only DB-backed helpers (`related(post, n)`, `query(...)`) run through a `HelperBridge` that calls the async store with `tokio::runtime::Handle::block_on` from the rendering thread (`spawn_blocking`), capped at 20 calls per render, published-only, recording dependency keys.
- **Plan ruling P3:** plugins are loaded at startup from the `plugins` table + MediaStore artifacts (enabled rows only), via `ferrite-plugin-host` with a store-backed `HostServices` (published-only `content.read`); hot reload on `plugins.changed` events is M1.5. Plugin install CLI/API is M2; tests install plugins by writing rows + artifacts directly.

## Review Focus

1. **Draft leak**: a draft, pending, scheduled-in-future, private or trashed item must never render publicly — direct URL, listing, feed, sitemap, search, `related()`, plugin `content.read`. *Test in Tasks 2, 8, 9.*
2. **Stale cache after edit**: editing a published post's title must update its page, its category archive, the home listing and the feed within one invalidation cycle; trashing removes it from all of them. *Test in Task 7.*
3. **Path tricks**: `/%2e%2e/`, `//x`, `/a/../b`, overlong paths (> 2048), non-UTF-8 percent-encoding, uppercase variants → 404 or canonical 301, never a 500 or an unrelated item. *Test in Task 4.*
4. **Hostile theme**: a template with an infinite loop or a 10 MB output → fuel stops it / output cap 8 MiB → 500 page, server keeps serving. *Test in Task 5.*
5. **Range abuse on /_media**: `bytes=0-0,1-1,…` (many ranges), `bytes=-0`, `bytes=99999999-` → single range only (multi-range → 200 full or 416, document), suffix ranges correct, 416 with `Content-Range: bytes */size`. *Test in Task 8.*

### Task 1: Core — permalink inputs (R9/I3)

Replace `PermalinkFn = Fn(&ContentItem) -> String` with a permalink module: `PermalinkInput { item: ContentItem, ancestors: Vec<(ContentId, String /*slug*/)> /* root first */, primary_term: Option<Term> /* first category */ }`, `trait Permalinks: Send + Sync { fn path(&self, input: &PermalinkInput) -> String; }`, `PermalinkRules` (impl, built from options `permalink.post`, `permalink.page`, defaults per Global Constraints) and `ContentService` loads `PermalinkInput` through the **Tx repos** (ancestors via parent walk ≤ 64, primary term via `for_item`) wherever it needs a permalink. When a published page's slug or parent changes, also record redirects for every published descendant (walk children via `ContentQuery{parent: Of(id)}` in the Tx, cap 1000 descendants, log if capped). When terms change under a `%category%` structure, record the move. Tests on both backends: each structure's path; descendant redirects; category change redirect; percent-encoding of unicode slugs.

### Task 2: Core — public read facade and preview (R9/I4)

`SiteReader` (in `ferrite-core/src/site.rs`) over `Arc<dyn Store>`: `single(kind, path_parts) -> Option<PageItem>`, `front_page(page) -> Listing`, `archive(kind, page) -> Listing`, `term_archive(tax, slug, page) -> Option<Listing>`, `author_archive(login, page)`, `date_archive(year, month: Option, page)`, `search(q, page) -> Listing`, `feed(kind | term, limit 20)`, `sitemap(kind, cursor)`, `related(item, n ≤ 10)`, `preview(actor, id) -> Result<PageItem, CoreError>` (`can_edit`, any non-trash status). `PageItem { item, html (rendered body), excerpt, author: Option<UserPublic>, terms, featured: Option<MediaPublic>, fields }`, `Listing { items: Vec<PageItem>, page, total, per_page }` built with batch loaders (no N+1; short-circuit empty id sets). `UserPublic` exposes only id, login, display_name. Every method forces published + `published_at <= now` (except preview) and returns the `DepKeys` it touched. Per-page default 10 (option `reading.per_page`, 1..=100). Tests on both backends: Review Focus 1 for every method; batch-loading query count (store wrapper counting calls) ≤ 6 per listing regardless of size.

### Task 3: Core — dependency-key contract (R9/I5)

Implement the contract in Global Constraints: `update` emits old∪new terms; lifecycle adds parent keys; redirect writes emit `redirect:` keys; options emit as today. Document the full contract (emitter side and renderer side) at the top of `events.rs`. Contract tests: for each write method, the exact key set emitted.

### Task 4: Router and permalink matching

`ferrite-http/src/route.rs`: pure `resolve(path, query, &RouteTable) -> Route` where `Route ∈ {Redirect(…), Single{kind, parts}, Front{page}, Archive{kind, page}, Term{tax, slug, page}, Author{login, page}, Date{y, m, page}, Search{q, page}, Feed(FeedKind), Sitemap(SitemapPart), Robots, Media{hash, name}, Theme{hash, path}, Health, Ready, NotFound, Canonical(String)}`. `RouteTable` built from permalink rules + reserved prefixes (`/_media`, `/_theme`, `/feed`, `/sitemap.xml`, `/robots.txt`, `/healthz`, `/readyz`, `/category/`, `/tag/`, `/author/`, `/search` (`?s=`), `/page/N/`). Lookup order: redirect table (async, done by handler before `resolve`) → static routes → permalink matcher → 404. Path normalisation: percent-decode once (invalid UTF-8 → 404), reject `.`/`..`/empty segments and backslashes, length ≤ 2048, canonical trailing slash (301). Exhaustive table tests incl. Review Focus 3.

### Task 5: `ferrite-theme`

Theme package (06 §1): `theme.toml` (name, version, menus, images, settings schema — reuse plugin settings field kinds), templates, assets. `ThemeSource` = embedded (`rust-embed` folder `themes/<name>`) | directory. `Theme::load(source) -> Result<Theme, ThemeError>` validates toml, requires `index.html`, compiles all templates (errors listed with file:line). `resolve_template(&Route-like key, &files) -> &str` per 06 §2 table (pure, table-tested). `Renderer::render(theme, template, ctx: RenderContext, bridge: &dyn HelperBridge) -> Result<RenderOutput{html, deps}, ThemeError>` on the calling (blocking) thread: MiniJinja env with custom loader (theme files only), `fuel` 5 000 000, output cap 8 MiB, auto-escape; globals/helpers per 06 §4 (`site`, `post`/`page`, `posts`, `menu(name)`, `related`, `query` (P2), `asset(path)` → `/_theme/<content-hash>/<path>`, `image(media, size)`, `head()` (pre-rendered string passed in), filters `date(fmt)`, `excerpt(n)`, `slugify`, `json`). `site` exposes only whitelisted options (`site.title`, `site.url`, `site.description`, `site.locale`, theme settings). Tests: hierarchy table; helper outputs; Review Focus 4; template error reporting.

### Task 6: Head rendering + plugin wiring (P3)

`ferrite-core` (or `ferrite-http`): `StoreHostServices` implementing `HostServices` over the store — `content.read` published-only (via `SiteReader` lookups), meta read/write within plugin scopes (host already enforces scopes), options read, kv via `PluginKvRepo::set_with_quota` (quota 10 MiB / 10 000 keys, 05 §3), settings from `plugin.<name>.settings.<key>` options. Startup: load enabled `plugins` rows → fetch artifact bytes from MediaStore → `Manifest::parse(row.manifest)` → `PluginHost::install`; failures logged, plugin skipped. Head: core SEO head (title, description from `seo.*` meta or excerpt, canonical, OG basics) → `apply_filter("render.head")` → structured `Head` → HTML with full escaping (05 §7: `script-tag.src` https or same-origin only, `json-ld` validated JSON with `</` escaped). `content.body`/`content.excerpt` filters applied to `PageItem.html`/excerpt; HTML results sanitised with ammonia unless the plugin's `render.html = "raw"` (05 §7, M0 ruling R4 closes here). Tests: a hello plugin installed via rows+artifact adds its meta to the rendered head on both profiles; hostile `big-output`/`panic` plugins don't break the page.

### Task 7: `ferrite-cache` + invalidation loop

`PageCache` (moka future cache, weigher = body bytes, `max_bytes`), `CacheKey`, `CachedPage { status, headers, body: Bytes, etag, deps, created, ttl: Option<Duration> }`, dependency index `HashMap<DepKey, HashSet<CacheKey>>` maintained on insert/evict (eviction listener), `invalidate(&[DepKey])`, `flush()`, single-flight per key (`moka` `try_get_with`). Invalidation loop (solo): poll `events.since(last_seq, 1000)` every 250 ms (config `cache.poll_interval_ms`), apply `invalidate` keys, `options.changed` → flush pages that read those options (keys `option:*`), `theme.changed`/`plugins.changed` → flush; start at `max_seq()` at boot. HTTP: `ETag` = hash of body, `If-None-Match` → 304. Tests: unit (index maintenance on eviction, single-flight); integration Review Focus 2 on both profiles (edit title → page/archive/home/feed updated after one poll; trash → gone everywhere).

### Task 8: `ferrite-http` app, handlers, `/_media`, `/_theme`

axum `Router` with state `AppState { store, media, reader, themes, renderer, plugins, cache, config }`; handlers for every `Route`; error pages via theme (`404.html`, `500.html`) or built-in; HEAD support; security headers; compression (tower-http, br/gzip, not for media); request tracing spans; `/healthz` (always 200) and `/readyz` (DB ping + migrations compatible + theme loaded). `/_media` per Global Constraints and Review Focus 5 (single range only; multi-range request → 200 full body, documented). `/_theme/{hash}/{*path}` serves theme assets with immutable caching. Feeds: RSS 2.0 for posts and per term (`/feed/`, `/category/x/feed/`), sitemap index + per-type sitemaps (≤ 50 000 URLs per file, published only), robots.txt (`Sitemap:` line; option `reading.discourage_indexing` → `Disallow: /`). Tests: HTTP integration (in-process server on 127.0.0.1:0) on both profiles for every route type, Review Focus 1 and 5, 404/500 pages, HEAD, ETag/304.

### Task 9: `blog` starter theme

`themes/blog/` embedded: `theme.toml`, `base.html`, `index.html`, `single.html`, `page.html`, `archive.html`, `taxonomy.html`, `search.html`, `404.html`, `500.html`, partials, `assets/style.css` (plain CSS, light/dark via `prefers-color-scheme`, readable typography), menus `primary`/`footer`, image size `card 640x360 crop`. Accessible markup (landmarks, skip link, alt text from media). Tests: golden render of each template with a seeded fixture (HTML snapshot via string assertions on key elements, not full-file snapshots).

### Task 10: `ferrite serve` and `ferrite seed demo`

`serve`: load config → `open_store(CreateIfMissing)` → `startup_check` → open MediaStore + `check()` → load theme (active from `themes` table, default `blog`) → load plugins → start invalidation loop → start `publish_due` ticker every 30 s → bind `server.listen` → graceful shutdown on SIGINT/SIGTERM (drain 10 s, stop tickers, close pools). Trusted proxies: honour `X-Forwarded-For/Proto/Host` only from `server.trusted_proxies`. `seed demo --data DIR`: creates an admin user (no password; login is M2), categories, tags, 12 posts with block bodies, 3 pages (one nested), a primary menu, a sample image uploaded through MediaStore with variants — idempotent (refuses if content exists unless `--force`). Tests: `serve` starts on a random port in a test, serves the seeded home page, shuts down cleanly on signal (both profiles).
