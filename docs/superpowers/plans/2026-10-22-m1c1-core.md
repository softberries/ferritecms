# M1c-1 — Store API Additions, Config, CLI and Core Services Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything below the HTTP/rendering layer that M1c-2 needs: the store API additions the M1a final review identified (ruling R19 of M1a), `ferrite-config`, the `ferrite` CLI (`init`, `migrate`), and `ferrite-core` services (content lifecycle with revisions, search indexing, slug handling, outbox events, capabilities; taxonomies, menus, options, redirects; block rendering).

**Architecture:** Store additions land in `ferrite-store` traits + both backends + contract tests (same patterns as M1a). `ferrite-config` parses `ferrite.toml` + `FERRITE_*` env into a validated `Config`. `ferrite-core` holds services that take `&dyn Store` (and `&dyn Repos` inside transactions); every invalidating write appends an outbox event in the same transaction. The binary crate `ferrite` wires config → store and exposes CLI subcommands. Core service tests run on both backends via `ferrite-store-tests`' `TestDb` harness.

**Tech Stack:** existing workspace + clap 4.6 (derive), deunicode 1.6, ammonia 4.2, html-escape 0.3, tokio, tracing, tracing-subscriber, anyhow (binary only).

**Spec:** `docs/design/02-storage.md`, `docs/design/01-architecture.md` (§1 crates, §4 config, §5 errors), `docs/design/06-themes-rendering.md` (§3 routing keys, §5 block rendering, §6 dependency keys), `docs/design/07-admin-api.md` §1 (roles & capabilities), `docs/design/04-cluster.md` §4 (event kinds), `docs/design/09-operations.md` §8 (CLI). M1a rulings: `docs/superpowers/rulings/m1a.md`.

## Global Constraints

- All M1a constraints and rulings remain binding for store work (R6 reader/writer split, R7/R13/R15 validation of every caller JSON/text, R8 `COLLATE "C"`, R9 RESTRICT, R11 savepoints for multi-statement ops, R18 Tx poisoning, `map_db_err`, runtime queries only, identical behaviour on both backends proven by contract tests).
- Libraries: `thiserror`; only `crates/ferrite` uses `anyhow`. No `unwrap`/`expect` in non-test code; no `#[allow(dead_code)]`; fmt + clippy `-D warnings`; `CI=true FERRITE_TEST_PG_URL=postgres://ferrite@localhost:54329/ferrite_test cargo test --workspace` passes.
- Dependency keys (06 §6, used in outbox events `kind = "invalidate"`): `post:<uuid>`, `archive:<type>`, `term:<uuid>`, `menu:<name>`, `option:<key>`, `theme`, `plugins`. Option changes use `kind = "options.changed"` with keys `option:<key>`.
- Capabilities (07 §1), enforced in core, roles admin/editor/author/contributor: `read_admin` (all); `edit_own` (all; contributor only while status ∈ {draft, pending}); `publish_own` (admin, editor, author); `edit_others`, `publish_others` (admin, editor); `upload_media` (admin, editor, author); `manage_terms`, `manage_menus`, `moderate_comments` (admin, editor); `manage_users`, `manage_settings`, `manage_themes`, `manage_plugins`, `import`, `manage_redirects` (admin).
- Revisions: a revision of the saved state is written on every successful content insert/update; then `prune(id, 50)`.
- Slugs: core-generated slugs = `deunicode` transliteration → lowercase → runs of non-`[a-z0-9]` become `-` → trim `-` → max 200 chars (cut at a `-` boundary when possible) → empty becomes `untitled`. Caller-supplied slugs: trimmed, lowercased (Unicode lowercase), must be non-empty, ≤ 200 chars, contain no `/`, whitespace or control chars; otherwise `CoreError::Invalid`. Uniqueness per (type, parent): on conflict append `-2`, `-3`, … using `slugs_with_prefix` (one query).
- Published items whose slug (or parent) changes get a `301` redirect `origin = slug-change` from the old URL path to the new one (path computed by a `PermalinkFn` the caller supplies; M1c-2 provides the real permalink function, tests use `/{type}/{slug}`).
- Config env overrides: `FERRITE_<SECTION>__<KEY>` (double underscore nests; keys lowercased); `*_file` keys read the secret from that file (trailing newline trimmed). Validation collects **all** problems with dotted key paths.
- M1a ruling R19 items in scope here: I4 (filtered/paginated search), I6 (ContentQuery filters, count, get_many, slugs_with_prefix, batch loaders), M4 (pending directives), nested-Tx orphan hazard, and I5 isolation policy (ruling P2 below).
- **Plan ruling P1:** I2 fail-fast detection is *not* implemented; the 5 s `Busy` + documented rule stands. Core services never call plugins or slow I/O while holding a Tx and always pass `&dyn Repos` down instead of calling `store.read()`/`begin()` inside a Tx.
- **Plan ruling P2 (I5):** isolation stays backend-default (SQLite serialized writer, PG READ COMMITTED). Correctness under concurrency comes from (a) optimistic `version` on content, (b) unique constraints + retry for slugs, (c) single-statement atomic store operations for read-modify-write (`PluginKvRepo::set_with_quota`). Documented in 02 §3.

## Review Focus

1. **Concurrent slug allocation**: two creates of "Hello World" in parallel → both succeed with `hello-world` and `hello-world-2` (retry on `UniqueViolation{content_items_slug_uq}` up to 5 times), on both backends. *Test in Task 6.*
2. **Contributor privilege escalation**: a contributor sets `status = published` via update, or edits a published own post, or edits someone else's draft → `CoreError::Forbidden`, nothing written. *Test in Task 6/7.*
3. **Slug change chain**: slug a → b → c on a published post → redirects `/post/a` → `/post/c` and `/post/b` → `/post/c` (old redirects re-targeted, no chains), and changing back to `a` deletes the now-self-referencing redirect. *Test in Task 6.*
4. **Hostile block JSON** (deeply nested 10 000 levels, `javascript:` link href, `<script>` in text, image `src` `data:`) → renderer returns escaped/stripped HTML, no stack overflow (depth limit 64 → render text content only below it). *Test in Task 5.*
5. **Config secrets**: `database.url_file` pointing at a missing file, or env `FERRITE_DATABASE__URL` plus `url_file` both set → one clear problem each; secrets never appear in `Debug`/error text. *Test in Task 4.*

### Task 3: Store — migration directives in status, nested-Tx hardening

**Interfaces — Produces:**
