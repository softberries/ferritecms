# M6-6 — Outgoing webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Administrators register HTTPS endpoints that receive signed Standard Webhooks `POST`s for content, media, comment, user and import events, delivered at least once through the job queue with retries, SSRF-checked egress, a delivery log, test delivery, redelivery, write-only rotating secrets and auto-disable with a notice; API under `/api/v1/webhooks` and an admin screen.

**Architecture:** Core (`ferrite-core::webhooks`) owns the catalogue, matching, signing, secrets, the `WebhookService` (CRUD, deliveries, the attempt state machine) and `emit`, which the write paths call inside their own `Tx` (event row + delivery rows + the first `webhook.deliver` job: the job queue is the outbox). `ferrite-http` implements the core `WebhookTransport` trait over the plugin egress client's checked resolver and serves the REST API. The `ferrite` binary registers the `webhook.deliver` handler (one job per attempt, schedule kept by the handler) and the hourly `webhooks.prune`. Admin SPA screens at `/admin/webhooks`.

**Tech Stack:** Rust 2024, axum 0.8, sqlx (SQLite + Postgres), reqwest 0.13 via `egress`, `hmac` + `sha2` + `base64` (already in `ferrite-core`), utoipa, React/TanStack admin, Vitest, Playwright. No new crates.

**Spec:** `docs/design/18-webhooks.md` (read it first; it wins over this plan on behaviour).

## Global Constraints

- Migration `0016_webhooks` on **both** backends, `-- ferrite:phase expand`, with `.down.sql`; contract tests on both (`FERRITE_TEST_PG_URL=postgres://ferrite@localhost:5432/ferrite_test`). Use no other migration number (0014/0015 are M6-1/M6-2, landing in parallel).
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`; `thiserror` in libraries, `anyhow` only in `crates/ferrite`; no `allow(dead_code)`; no `unwrap`/`expect` in non-test code.
- Capabilities are checked in core (`WebhookService`), never in handlers.
- REST API changes: DTOs with `utoipa` annotations; regenerate `crates/ferrite-http/openapi.json` with `FERRITE_UPDATE_OPENAPI=1 cargo test -p ferrite-http --test api openapi`; then regenerate `admin/src/api/schema.d.ts` with the repo's generation script (`pnpm -C admin gen:api` or what `admin/README.md` names).
- Constants (design §4.5): schedule `[0, 5 s, 5 min, 30 min, 2 h, 5 h, 10 h, 14 h]` + 0–10 % jitter; timeout 15 s; body ≤ 64 KiB; response read 4 KiB, excerpt 1 KiB; 20 endpoints; 50 patterns; 10 tests/user/min; 1 000 per bulk redeliver; retention 30 days; auto-disable at 5 days **and** 10 consecutive failed attempts; previous secret valid 24 h.
- Secrets never appear in DTOs (except the create/rotate answers), audit details, logs, errors or `Debug` output (wrap in `ferrite_domain::Secret`). Audit and logs carry the URL host only.
- The content emitter skips kind `media`; `MediaService` emits `media.*` itself.
- Merge-friendliness: wave A (M6-1, M6-2) runs in parallel and also touches `content.rs`, `content/lifecycle.rs`, `actor.rs`, `repos.rs`, the `Repos` implementors and `catalogue.rs`. Keep edits to those files additive and small (one call per write path, one accessor, new enum variants appended at the end); put everything else in new files.
- Admin: i18n keys in `admin/src/i18n/en/webhooks.json` (+ `shell.json` nav label, `account.json`/wherever `tokenDialog.areas` lives, `admin.json` audit texts); design rules of `docs/design/11-admin-ui.md` (tokens only, 44 px touch targets, axe clean).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A write that fails after `emit` (rolled-back `Tx`) leaves no `webhook_events`, `webhook_deliveries` or `jobs` row.
- A delivery job run twice for the same attempt (crash after recording, lease expiry) sends at most one extra request and records one attempt row (`record_attempt` conditional; unique job keys).
- `http://`, `127.0.0.1`, `[::1]`, `169.254.169.254`, `10.x`, a public name resolving to a private address, a mixed public/private answer, a `302` to an internal host: never connected to (without `[webhooks] local_targets`); with `local_targets` the metadata range stays refused.
- The secret is shown once; a rotation signs with both secrets for 24 h; `GET` never returns one; the audit holds no secret and no full URL.
- An editor, a `settings:write`/`system:write` token and an OAuth grant cannot list or create webhooks.
- A database copied by `import-site`/`db copy`/`restore` sends nothing until an admin re-enables each endpoint.
