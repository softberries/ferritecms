# M2a-2b — Media, Comments, System API & Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Authors upload media over the API (streamed, size- and type-checked, retry-safe with `Idempotency-Key`, SVGs sanitised and then served inline), variants are built by a bounded `media.variants` job; visitors comment through the API or a theme form and moderators work a queue; admins read system status, nodes, jobs (and retry dead ones), plugin metrics, a metrics snapshot and the audit log; plugins get a real `http` import that cannot reach internal addresses; the remaining M2 hardening and deferred items close. This is the last backend plan of M2.

**Architecture:** One expand migration `0006_media_comments` (idempotency keys, `media.sanitized`, comment and job indexes). `ferrite-media` gains the SVG sanitiser over quick-xml. `ferrite-core` gains `MediaService` (records uploads and variants in one `Tx` with `post:<media id>`), `CommentService`, `SystemService`, a `diagnostics::scrub`, the `ManageSystem` capability and two settings. `ferrite-http` gains the streaming `media::Uploader`, the `/media`, `/comments` and `/system` endpoints, `Idempotency-Key`, the public `/_comment` form, the `comments()` theme helper, and `plugins::egress::Egress` (reqwest with a checking resolver) behind the plugin `http` import. The binary gains the `media.variants` handler with its image semaphore. Byte I/O (streaming, sanitising, image processing) never runs inside a `Tx` (M1c-1 P1): `ferrite-http`/the binary stage bytes, core records rows.

**Tech Stack:** axum 0.8.9 (multipart), utoipa 6.0.0 / utoipa-axum 0.3.0, sqlx 0.9, quick-xml 0.41.0, reqwest 0.13.5 (`rustls`), zeroize 1.9.1, ammonia 4.2.4, wasmtime 50, tokio.

**Spec:** `docs/design/03-media.md` §3 (upload cap, 5 GB ceiling), §4 (variants, semaphore), §5 (serving, SVG); `docs/design/07-admin-api.md` §1 rows marked M2a-2b (Media, Comments, Plugin metrics, System), "Idempotency", §2 (cookie, site key); `docs/design/05-plugin-host.md` §6 "HTTP capability details", §7, §8, §12; `docs/design/06-themes-rendering.md` §4, §6; `docs/design/04-cluster.md` §6; `docs/design/02-storage.md` §4, §7; `docs/design/09-operations.md` §6, §8; ROADMAP "M2a-2b" (every item, including the two M2a-2a final-review carries); rulings `docs/superpowers/rulings/{m1b,m1c2,m15,m2a,m2a2}.md` stay binding. ## Review Focus

1. **An uploaded SVG never runs script or loads anything.** `<script>`, `foreignObject`, `on*` attributes, `javascript:` (also entity-encoded) and external `href`/`xlink:href` (any namespace prefix bound to XLink), `<animate>`/`<set>`, `<style>` or `style` with external `url(`/`@import`, data-URI SVG inside `<image>`, a DOCTYPE (entity bombs, XXE), unknown entities and depth bombs are removed or refused; only sanitised SVG is ever served inline, and then under `sandbox` CSP. *Tests in Task 2 (`hostile_svgs_are_neutralised`, `doctype_and_entities_are_refused`, `namespace_tricks_do_not_pass`) and Task 6 (`sanitised_svg_is_inline_with_sandbox`, `unmarked_svg_stays_an_attachment`).*
2. **An upload cannot exceed its limit or disguise its type, and a retried upload creates one item.** A body over `media.max_upload` is cut while streaming with nothing recorded; HTML sent as `image/png` or named `.png` is `415`; a PNG named `.svg` is a PNG; replaying an `Idempotency-Key` returns the first `201` without a second item, a concurrent duplicate is `409`, a reuse on another path is `422`. *Tests in Task 4 (`upload_over_limit_is_413_and_records_nothing`, `type_confusion_is_refused`) and Task 5 (`idempotent_retry_creates_one_item`, `concurrent_duplicate_is_409`).*
3. **Comment spam and XSS stay inert.** Script in body, name or URL renders escaped; a `javascript:` author URL is refused; pending comments never appear; the honeypot silently drops bots; the per-IP limit holds across two nodes; a form posted from another origin, or an API call with the session cookie but without the CSRF token, is refused. *Tests in Task 7 (`comment_xss_is_escaped`, `comment_limits_hold_across_nodes`, `cookie_without_csrf_is_403`) and Task 8 (`foreign_origin_form_is_refused`, `honeypot_drops_silently`).*
4. **A plugin's `http` cannot reach internal addresses.** Loopback, private, link-local, metadata (`169.254.169.254`), CGNAT, IPv4-mapped/NAT64/6to4 forms and mixed DNS answers are refused after resolution and the connection goes to the checked address only; redirects to a host outside the allowlist, to `http:` or to another port are refused; userinfo and trailing-dot tricks fail; a 2 MiB+1 body is cut. *Tests in Task 11 (`ssrf_targets_are_refused`, `rebinding_answer_is_refused`, `redirects_stay_on_the_allowlist`).*
5. **Admin diagnostics leak no storage paths, endpoints or secrets.** Node `error` texts in `nodes.meta`, `GET /plugins`, `GET /themes` and `GET /system/nodes` have URLs, absolute paths and IP addresses replaced, even when an older node wrote them unscrubbed; job errors are already sanitised by the store and job payloads are never returned. *Tests in Task 9 (`node_errors_are_scrubbed`, `old_node_meta_is_scrubbed_on_read`).*

## Plan rulings

- **P1 — One plan, 16 tasks; no split.** The ROADMAP's M2a-2b list fits 16 tasks once the store work rides with the tasks that use it (only `0006`'s tables and their repositories come first). Cost: Task 7 (comments service + API) and Task 12 (five hardening items) are the largest.
- **P2 — `0006_media_comments`** (both backends, same name, `.down.sql`, expand, `lossy-down`): `idempotency_keys`, `media.sanitized`, `comments_status_created_idx`, `comments_author_email_idx`, `jobs_status_created_idx`. No CHECK on `comments.status` (SQLite would need a table rebuild); core validates. Cost: none.
- **P3 — Bytes are staged in `ferrite-http`, rows recorded in core** (as M2a-2a P8): `media::Uploader` streams, sniffs and sanitises outside any `Tx`; `MediaService::record_upload` writes the artifact row, the item, the media row, the event and the variants job in one `Tx`. A refused or failed upload never deletes a blob (content addressing means another row may own it; M4's GC collects orphans). Cost: orphan blobs until GC.
- **P4 — Types are decided from the first 8 KiB before anything is stored**, by content only: `inline_safe` types, or SVG by `looks_like_svg` (then sanitised). Cost: none.
- **P5 — Uploads are published media items at once** (WordPress attachments are public on upload), so `/_media` serves them as soon as a post links them. Every role with `upload_media` also holds `publish_own`. Cost: an upload is public by hash before the post that uses it is published.
- **P6 — The accepted upload types are `inline_safe` plus sanitised SVG.** Archives and office documents are refused (`415`) in v1; anything served from the site's origin as an attachment is still a download a visitor trusts. Cost: no ZIP/DOCX uploads until a `media.extra_types` setting (later).
- **P7 — SVG sanitising is our own allowlist over quick-xml 0.41** (no maintained sanitiser crate; M2a-2a plan check), dropping unknown subtrees, refusing DOCTYPEs and unknown entities, keeping only local references; sanitised SVG is stored instead of the original and marked `media.sanitized`; only marked SVG is served inline, with `sandbox; default-src 'none'; img-src data:; style-src 'unsafe-inline'`. Cost: some valid SVG features (`<style>`, animation, external fonts, links) are stripped.
- **P8 — Variants are a `media.variants` job per raster upload** (unique per item and artifact), bounded per node by `media.image_workers` (default 1: one image at the 100 MP cap peaks near 1.2 GB, M1b R4) and skipped for originals over 64 MiB; sizes are the core sizes plus the active theme's `[images]` on the node that runs the job; recording is conditional on the row still holding that artifact. Regenerating variants after a theme change is M4. Cost: a theme switch leaves older uploads without its new sizes (`image()` falls back to the original).
- **P9 — `media.max_upload` defaults to 256 MiB and is capped at 1 GiB** (03 §3: below the 5 GB single-copy ceiling); at most 8 uploads in flight per node. Cost: larger media need a later multipart-copy path.
- **P10 — `Idempotency-Key` on `POST /media` only** (imports are M3): scoped to (user, key), stored as SHA-256; a finished key replays the stored `2xx` without reading the body; a pending one is `409` (stale after 1 h); method or path mismatch `422`; failures release the key; rows pruned after 24 h by `sessions.prune`. A reused key with a different file is not detected. Cost: a client bug reusing a key gets the first upload's answer.
- **P11 — Comments are plain text on `post` items only**, rendered by core (escaped, paragraphs and line breaks, no autolinks); statuses `pending`, `approved`, `spam`, `trash`; replies to approved comments up to depth 5; `comments.enabled` (default on) and `comments.moderation` = `all` (default) | `known` (approve when the e-mail has an approved comment and the body has at most 2 links); moderators' own comments are approved. Comments on pages and custom types, per-item closing and comment hooks for plugins are later items (P29). Cost: no anti-spam plugin hook in v1.
- **P12 — Two submit paths, one service.** `POST /api/v1/content/{type}/{id}/comments` (JSON; same-origin unless bearer; an optional session with CSRF or a token makes it the user's comment) and the theme form `POST /_comment` (form-encoded, same-origin, always anonymous: a theme form cannot send the CSRF header, so the session cookie is ignored there). Success redirects use fragments (`#comment-pending`) so cached pages stay shared. Cost: logged-in users type their name in the theme form.
- **P13 — Spam defences:** per-IP 3/min and 20/h DB-backed limits (across nodes), a honeypot field that silently discards, moderation by default, the link count rule, keyed IP hashes (`ferrite:comment-ip:v1`) for moderators instead of addresses. An unknown client address is `503` (M2a-2a R13). Cost: a shared NAT address shares the limit.
- **P14 — Comment moderation is not audited** (volume; the comment row carries its own status); job retries are (`job.retry`). Cost: no history of who approved a comment.
- **P15 — System reads need the new `manage_system` capability** (admin) with `system:read`; retry needs `system:write`. No new lock. Cost: `Capability::ALL` grows to 16 (DTO and test lists update).
- **P16 — The `http` import refuses a DNS answer when any address is non-public**, and connects only to the checked addresses through reqwest's resolver hook (no second lookup, so no rebinding window); `https` on 443 only; redirects re-checked per hop against the calling plugin's list; no proxy, cookies, referer or decompression; 5 s, 1 MiB out, 2 MiB in. Cost: a host with one private address in its answer is unreachable; no plain-HTTP or custom-port APIs.
- **P17 — reqwest 0.13.5 with `rustls`** (already in the tree through object_store, so no new code is linked); the TLS roots are the platform verifier's. Cost: the binary depends on the host's CA store (distroless ships one).
- **P18 — Node diagnostics are scrubbed at the source and again on read** (`diagnostics::scrub`: URLs, absolute paths, IP addresses), keeping the plugin- or theme-caused text admins need; full errors stay in the node's log. Cost: an operator reads the log for the exact path or endpoint.
- **P19 — Jobs list never returns payloads** (they can hold traffic events and item ids); `handled` shows whether a live node runs the kind (from `nodes.meta.job_kinds`), so a queued kind no node knows stays visible (M1.5 P5). Retry is dead → queued with attempts reset and `last_error` kept. Cost: payload debugging needs the database.
- **P20 — Metrics are a node-local snapshot in M2a-2b**: plugin call stats per hook since start and cluster-wide failure buckets for 24 h; the summary shows this node's renders, page-cache hits and size, plugin totals and DB job counts. The registry, `/metrics`, `node_metrics` rows and time series stay M4 (09 §6). Cost: the M2b dashboard shows only the answering node until M4.
- **P21 — Shared HTML URL policy** (`ferrite_domain::html`): `http`, `https`, `mailto`, root-relative, fragment, query and path-relative; scheme-relative `//…`, backslashes, `ftp:`, `tel:`, `data:` and `javascript:` dropped, for content blocks and plugin `html` alike. Cost: `tel:` links need a later setting.
- **P22 — R24 N1/N2.** Head script sources are resolved like a browser does (`Url::join` against `site.url`) before the `/_p/` and `/_media/` refusal; a slot-wait-shortened call is counted as a failure once the plugin itself ran at least half its deadline (a looping plugin cannot hide behind load). Cost: under heavy load a slow-but-legitimate plugin can accumulate failures sooner.
- **P23 — `__Host-ferrite_session` on `https` sites with no transition read** (nothing is released; reading the old name too would keep cookie tossing open). Cost: one re-login after upgrading a pre-release site.
- **P24 — Zeroization covers `SiteKey`, subkeys, HMAC state, `Secret` and password inputs from the API**; serde_json's request buffer and argon2's internal buffers are not wiped (documented). Cost: residual copies in freed buffers.
- **P25 — Term archives list every type of the taxonomy** through `ContentQuery.kinds`; the theme `query(term=…)` helper reads exactly `limit` items of the requested kind; term slug changes record 301s. Cost: one more store filter on both backends.
- **P26 — Deferred to M3:** redirects for `permalink.*` structure changes (every published URL moves; with the importer's redirect machinery: keep the previous structure and redirect by matching it) and `Idempotency-Key` for imports. Cost: changing the permalink structure breaks old links until M3.
- **P27 — Deferred to M4:** `date` filter time zones (needs a tz database dependency, decided with the static-build choices: chrono-tz vs jiff), `seed demo` atomicity (every core service would need an outer-`Tx` entry point for a dev tool; `--force` reruns it), variant regeneration (`ferrite media regenerate`), the metrics registry and time series (P20). Cost: dates in templates stay UTC; a failed seed leaves a partial demo.
- **P28 — New test plugins:** `fetcher`, hostile `ssrf`; `html-inject` gains a footer hook. Cost: longer plugin builds.
- **P29 — Later (after M2):** comments on pages and custom types (a per-type flag), per-item closing, comment action hooks and admin notification mails, extra upload types (P6). Cost: listed in the roadmap.
- **P30 — The sweep's unauthenticated list grows by the comment submit only**, which checks the origin like login unless a bearer token is sent; a cookie without the CSRF token is `403 csrf` there too. Cost: none.
