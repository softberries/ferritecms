# M0 — Plugin Host Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A wasmtime-based plugin host that loads WASM component plugins, links only the interfaces their manifest grants, bounds every call (memory, fuel, deadline), contains hostile plugins, and runs a Rust SDK hello-world filter in < 1 ms warm.

**Architecture:** `ferrite-plugin-host` (library) owns one `wasmtime::Engine`, an epoch ticker thread, and an in-memory plugin registry. Each hook call creates a fresh `Store` + instance from a cached `PluginPre` (generated by `bindgen!`), with a per-plugin `Linker` that only contains granted `ferrite:plugin/*` interfaces plus WASI. Host-side data access goes through a `HostServices` trait (in-memory impl in M0; real store in M1). Plugins are built from a separate cargo workspace `plugins/` targeting `wasm32-wasip2`, using `ferrite-sdk`.

**Tech Stack:** Rust 1.98 stable, edition 2024; wasmtime 50 + wasmtime-wasi 50; wit-bindgen 0.63 (guest); tokio; thiserror; tracing; serde + toml; criterion (bench).

**Spec:** `docs/design/05-plugin-host.md` (primary), `docs/design/00-overview.md`, `docs/design/10-testing.md`, `docs/ROADMAP.md` M0.

## Global Constraints

- Rust stable, edition 2024, Cargo workspace under `crates/`; `rust-toolchain.toml` pins `stable` with targets `wasm32-wasip2`.
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` pass on the root workspace **and** on `plugins/`.
- Errors: `thiserror` in libraries; `anyhow` only in binaries/benches/tests. No `#[allow(dead_code)]` — delete unused code instead.
- Logging via `tracing` only (no `println!` outside tests/benches).
- WIT lives in `wit/ferrite-plugin@0.1.0/`; package `ferrite:plugin@0.1.0`; world `plugin`.
- Default limits (05 §6, 01 §4): memory `32 MiB`, fuel `50_000_000`, render deadline `50 ms`, action deadline `5_000 ms`, epoch tick `5 ms`, hard deadline = deadline × 1.5, `disable_after_failures = 20` within `failure_window = 10 min`.
- Output caps (05 §6): `head` ≤ 64 KiB total serialized strings; `html`/`text` ≤ max(4 × input length, 64 KiB), never above 2 MiB *(plan call: the spec's "4× input or 2 MB" read as this formula)*.
- Host-import budgets per call (05 §6): `content` ≤ 100 calls; `kv` ≤ 100 ops and ≤ 1 MiB written; `http` ≤ 3 requests.
- Allowed WASI imports (05 §5, verified list from spike): `wasi:clocks/*`, `wasi:random/*`, `wasi:io/*`, `wasi:cli/{stdout,stderr,stdin,environment,exit,terminal-input,terminal-output,terminal-stdin,terminal-stdout,terminal-stderr}`, `wasi:filesystem/*` (linked, no preopens). Rejected: `wasi:sockets/*`, `wasi:http/*`, anything else.
- Plugin names: `[a-z0-9-]{2,48}`.
- Hostile plugins required by CLAUDE.md: infinite loop, OOM, panic, undeclared import.

### Verified API facts (spike on 2026-10-22, wasmtime 50 / wit-bindgen 0.63)

- `cargo build --target wasm32-wasip2` emits a component directly; **unused WIT imports are dropped** (a guest that never calls `kv` doesn't import it).
- Host: `wasmtime::component::bindgen!({ world: "plugin", path: …, imports: { default: async }, exports: { default: async } })` → `PluginPre::new(linker.instantiate_pre(&component)?)`, `pre.instantiate_async(&mut store).await`, `plugin.ferrite_plugin_guest().call_apply_filter(&mut store, …).await`.
- Per-interface linking: `ferrite::plugin::log::add_to_linker::<_, HasSelf<State>>(&mut linker, |s| s)`.
- WASI: `wasmtime_wasi::p2::add_to_linker_async(&mut linker)`; state implements `WasiView` returning `WasiCtxView { ctx, table }`. `Config::async_support` was not needed.
- `Config::consume_fuel(true).epoch_interruption(true)`; `store.set_fuel`, `store.fuel_async_yield_interval(Some(10_000))`, `store.set_epoch_deadline(n)`, `store.epoch_deadline_trap()`; `StoreLimitsBuilder::memory_size(..).instances(..)` + `store.limiter(..)`.
- Traps are recoverable via `err.downcast_ref::<wasmtime::Trap>()`: guest `panic!` → `Trap::UnreachableCodeReached`; busy loop with 50 M fuel → `Trap::OutOfFuel` (~27 ms).
- SDK pattern: in `ferrite-sdk`, `wit_bindgen::generate!({ …, pub_export_macro: true, default_bindings_module: "ferrite_sdk::bindings" })` inside `pub mod bindings`; a plugin crate calls `ferrite_sdk::bindings::export!(Ident)` (macro takes an **ident**, not a type).
- Unoptimised measurement: fresh instantiate + call ≈ 0.3–0.4 ms in release, without the pooling allocator.

## Review Focus

1. **Non-component bytes uploaded** (core wasm module, empty file, random bytes) → `inspect` returns `InspectError::NotAComponent`/`Invalid`, never panics. *Test in Task 5.*
2. **Many concurrent calls to one plugin** (64 parallel `apply_filter` on a multi-thread runtime) → all return correct values; no panic, no deadlock. *Test in Task 6.*
3. **Guest floods stdout/stderr** (10 MiB of output in one call) → host memory bounded, output truncated at 64 KiB per call in logs, call still succeeds. *Test in Task 8 (`noisy` plugin).*
4. **Plugin fails during instantiation** (data segment / initial memory larger than the 32 MiB limit) → treated as a call failure (previous value returned, failure recorded), not a host error. *Test in Task 8 (`fat-init` plugin).*
5. **Manifest/hook mismatch**: hook not in the catalogue, or hook whose capability isn't declared, or two failures for the same manifest → one validation error listing every problem with its key path. *Test in Task 3.*
