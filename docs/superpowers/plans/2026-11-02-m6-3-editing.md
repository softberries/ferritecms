# M6-3 — Editing (live preview, releases, approval workflows) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The editor shows a live preview of the unsaved item beside the text; editors group changes into releases applied in one transaction (now or scheduled) and browse the whole site as it will look; content types can require approvals before publishing; previews can be shared with signed, expiring links.

**Architecture:** Migration `0017_releases_workflows` adds releases, entries, locks, workflows, reviews and preview links. `ferrite-core` gets `release/` (`ReleaseService`, the `ApplyTx` wrapper with a collecting mode for one merged invalidation event and a sandbox mode for previews, `SandboxStore`), `workflow/` (`WorkflowService`, `ReviewService`, the publish gate) and `preview_link.rs`. `ferrite-http` renders through a `ReadView`, so a preview can render the real pipeline over a rolled-back sandbox transaction; new `/_preview` routes, the preview cookie, REST endpoints and MCP tools. The admin gets the preview pane, release and review screens and the workflow editor.

**Tech Stack:** Rust 2024, axum 0.8, sqlx (SQLite + Postgres), `utoipa`, `rmcp` 3.8, MiniJinja; React/TanStack admin, `@dnd-kit` (already a dependency), Vitest, Playwright. No new dependency.

**Spec:** `docs/design/15-editing.md` (read it first; it wins over this plan on behaviour). Wave B: M6-1 (locales, migration 0014), M6-2 (0015) and M6-6 (webhooks, 0016) are merged before this starts.

## Review Focus

- A release whose 37th entry fails (a slug taken since staging) → nothing of it is written, on SQLite and Postgres; the release stays `open` (apply now) or becomes `failed` with all problems listed (scheduled).
- Applying a release appends exactly one `invalidate` event and no other; a release preview appends none and leaves the Postgres events sequence without a gap.
- An item in a scheduled release cannot be updated, published, trashed or restored to a revision through the API or MCP (409 `release-locked`); unscheduling frees it.
- Workflow type: an editor's own draft cannot be published until another editor approves; an edit after approval makes the review stale and publish fails again; a published item cannot be edited in place (409 `staging-required`); an admin publishes with `override_reason` and the audit row says so; MCP cannot override.
- A preview link of someone who has since been disabled, or who lost `edit_others`, stops working at once; an expired or revoked one renders the site normally and clears the cookie.
- A page rendered under a release preview is never stored in the page cache, is `no-store` and `noindex`, and shows the core preview bar even under a theme without `request.preview`.
- A plugin calling `kv.set` during a release preview on SQLite gets an error at once (no 5 s writer wait).
