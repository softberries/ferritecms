# M1b — Media Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ferrite-media`: a content-addressed `MediaStore` over the `object_store` crate with a local-folder backend and an S3-compatible backend behaving identically, plus pure image processing (safe decode, orientation, metadata stripping, resized variants), all tested against a real in-process S3 server.

**Architecture:** One `MediaStore` struct wraps `Arc<dyn ObjectStore>` (`LocalFileSystem` or `AmazonS3`) plus a key prefix and public-URL mode. Writes stream through SHA-256, stage under `tmp/`, then land at `artifacts/<hh>/<hash>`. A shared contract test suite runs every store test against both backends; S3 runs against an `s3s-fs` server started inside the test process (no Docker). Image work is a pure module (`bytes in → variants out`) so the job runner in M1c can call it.

**Tech Stack:** object_store 0.14 (`aws` feature), sha2 0.11, infer 0.22 (MIME sniffing), image 0.25.10, bytes, futures, tokio; dev: s3s 0.17, s3s-fs 0.17, hyper-util (server-auto), tempfile.

**Spec:** `docs/design/03-media.md` (primary); `docs/design/01-architecture.md` §4 (`[media]` config); `docs/design/00-overview.md` (D4, D10).

## Global Constraints

- Library crate: `thiserror` errors (`MediaError`), `tracing` logs, no `unwrap`/`expect` in non-test code, no `#[allow(dead_code)]`; fmt + `clippy --all-targets -D warnings` clean; existing workspace tests keep passing.
- Key layout (03 §3): `<prefix>artifacts/<first two hex chars>/<64-hex sha256>` and staging `<prefix>tmp/<uuid v7>`. `prefix` is either empty or ends with `/`, and never starts with `/`.
- Hash = lowercase hex SHA-256 of the exact bytes stored; type `ferrite_domain::ArtifactHash` (from M1a).
- Small-file threshold 8 MiB: below it, buffer + hash + put directly to the final key; at or above it, stream to `tmp/<uuid>` via multipart, then copy to the final key and delete tmp (03 §3).
- Idempotent writes: putting bytes whose artifact already exists does not rewrite it and returns the same `ArtifactRef`.
- Image limits (03 §4): max decoded pixel count 100 000 000 (100 MP); also `image::Limits.max_alloc` 512 MiB; EXIF orientation applied; metadata stripped (re-encode from pixels); default variants `thumbnail 150x150 crop`, `medium 768w`, `large 1600w` (width-bounded, aspect kept, never upscaled).
- Verified facts (spike, 2026-10-22): an `s3s_fs::FileSystem` behind `s3s::service::S3ServiceBuilder` (with `SimpleAuth::from_single(key, secret)`) served over `hyper_util::server::conn::auto::Builder` on `127.0.0.1:0` works with `AmazonS3Builder::new().with_endpoint("http://addr").with_allow_http(true).with_bucket_name(b).with_region("us-east-1").with_access_key_id(..).with_secret_access_key(..).with_virtual_hosted_style_request(false)`; in object_store 0.14 `put`/`get` are on the `ObjectStoreExt` trait; `s3s_fs::Error` does not implement `std::error::Error` (map with `{e:?}`). image 0.25.10 has `ImageDecoder::orientation()`, `DynamicImage::apply_orientation(Orientation)`, `ImageReader::limits(Limits)`; its WebP encoder is **lossless only**.
- **Plan ruling P1:** no WebP variants in v1 (image's encoder is lossless-only; lossy WebP would need a C dependency). Variants are encoded in the source format: JPEG (quality 82), PNG, GIF → PNG first frame. Design 03 §4 "output WebP" is updated in Task 5.

## Review Focus

1. **Interrupted upload** (stream errors mid-way) → no object at the final key, no artifact returned, tmp object deleted (best effort, logged on failure). *Test in Task 3.*
2. **Same bytes uploaded concurrently** (8 tasks, same 10 MiB payload) → all return the same hash, exactly one final object exists, no tmp leftovers. *Test in Task 3.*
3. **Range request past the end / inverted** → `MediaError::Range`, not a panic or a truncated body. *Test in Task 2.*
4. **Decompression bomb** (tiny PNG declaring 20000×20000) → `MediaError::ImageTooLarge` before allocating the full buffer. *Test in Task 4.*
5. **Wrong extension / spoofed MIME** (PNG bytes named `.jpg`, an HTML file named `.png`) → sniffed MIME wins; non-image bytes are never treated as images. *Test in Task 2 (sniff) and Task 4 (process).*

### Task 3: Streaming uploads (≥ 8 MiB) and concurrency

**Files:** `src/store.rs`, `tests/store.rs`.

**Interfaces — Produces:**
```rust
impl MediaStore {
    pub async fn put_stream<S>(&self, stream: S) -> Result<ArtifactRef, MediaError>
        where S: futures::Stream<Item = Result<bytes::Bytes, std::io::Error>> + Send + Unpin;
}
```
Semantics: hash while streaming; first 8 MiB buffered — if the stream ends below 8 MiB use the small path; otherwise start a multipart upload to `tmp/<uuid>` (object_store `put_multipart`), finish, then if the final key exists delete tmp, else `copy` tmp → final and delete tmp. On any error: abort multipart / delete tmp (best effort), return error.

- [ ] **Step 1: Failing tests (both backends):** `stream_large_roundtrip` (20 MiB pseudo-random deterministic bytes in 64 KiB chunks → hash equals sha256, `get` returns identical bytes, no objects under `tmp/`); `stream_small_uses_direct_path` (100 KiB stream → no multipart; still correct); `interrupted_stream_leaves_nothing` (Review Focus 1: stream yields 10 MiB then `Err` → error returned, no final object for the partial hash, `tmp/` empty); `concurrent_same_payload` (Review Focus 2: 8 tasks × same 10 MiB → identical hash, one final object, `tmp/` empty).

### Task 4: Image processing

**Files:** `src/image.rs`, `tests/image.rs`.

**Interfaces — Produces:**
```rust
pub struct VariantSpec { pub name: String, pub width: u32, pub height: Option<u32>, pub crop: bool }
pub fn default_variants() -> Vec<VariantSpec>;   // thumbnail 150x150 crop; medium 768w; large 1600w
pub struct Variant { pub name: String, pub data: bytes::Bytes, pub mime: String, pub width: u32, pub height: u32 }
pub struct Processed { pub width: u32, pub height: u32 /* after orientation */, pub variants: Vec<Variant> }
pub fn process_image(data: &[u8], specs: &[VariantSpec]) -> Result<Processed, MediaError>;   // pure, CPU-bound (caller uses spawn_blocking)

```
Rules: sniff first — non-raster → `UnsupportedImage`; read dimensions via `ImageReader::into_dimensions` style probe before full decode and reject `w*h > MAX_PIXELS` with `ImageTooLarge`; decode with `Limits{max_alloc: 512 MiB}`; apply EXIF orientation; for each spec: skip if source is smaller than target width (no upscaling) unless `crop` (thumbnail is always produced, cropped to cover then center-cropped); encode in source format per ruling P1 (JPEG q82, PNG, GIF→PNG, WebP source→PNG); re-encoding drops all metadata.
