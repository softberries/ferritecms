# M4-4 Follow-ups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the follow-ups that can lose data, show a visitor or admin something wrong, leak across a permission boundary, flake CI or make the first release irreproducible; move the rest of ROADMAP "M4-4 — follow-ups" to "Later" or a "Before v0.1.0" checklist.

**Architecture:** No new subsystem. Eight independent task areas (ops tooling, public rendering, sitemap reads, API/security consistency, import robustness, admin polish, test reliability, release packaging) plus the exit. One store trait addition (T3, both backends, contract tests); no migration; one OpenAPI text change (T4).

**Tech Stack:** Rust 2024 workspace (tokio, sqlx, object_store, MiniJinja), the admin SPA (React + TS, Vitest, Playwright), GitHub Actions shell scripts.

**Spec:** `docs/ROADMAP.md` "M4-4 — follow-ups" (each item points at its exit doc and ruling); the triage that selected the items: `.superpowers/m4-4-recon/triage.md`. Facts with file:line per item: `.superpowers/m4-4-recon/{t1-ops,t2-t3-site,t4-t5-sec-import,t6-t8-admin-tests}.md` (the recon; every task reads its file first).

## Global Constraints

- CLAUDE.md conventions: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, rustdoc `-D warnings`; `thiserror` in libraries, `anyhow` only in the binary; no `#[allow(dead_code)]`.
- Storage changes: both backends, contract tests in `ferrite-store-tests`, the `Counted` wrapper updated; no migration in M4-4 (nothing here needs one; migrations 0001–0012 freeze at v0.1.0).
- API changes: regenerate `openapi.json` (`FERRITE_UPDATE_OPENAPI=1 cargo test -p ferrite-http --test api openapi`) and `admin/src/api/schema.d.ts`.
- Exit codes stay the documented 0 ok / 2 done-with-problems / 3 conflict-or-incompatible / 1 error convention.
- Every behaviour change updates its design doc section and, where the docs site states it, the page and its `site/VERIFIED.md` row.
- Tests first; a red run recorded per code change.

## Review Focus

1. A redirect loop or a lost page: `/home/` → `/` must never redirect `/` itself, a child `/home/x/`, a preview or a non-front page that shares the slug.
2. Data safety tools that refuse too much: a new refusal (T1) must not block the documented runbook path (stopped service, operator shell); each refusal says what to do.
3. Sitemap correctness after the T3 rewrite: same URLs, same `lastmod`, same file split as before on a site with more than one file per kind (both backends).
4. Permission leaks: `check_relations` and the blank-`q` change must not reveal or accept more than before.
5. Flake fixes that hide real failures: a longer timeout is fine, a removed assertion is not.

## Plan rulings (also recorded in `docs/superpowers/rulings/m4.md` "M4-4 plan rulings")

- **P66 (scope).** The triage's "Fix" list is M4-4. "Later" items move to ROADMAP "Later" with their pointers; user-owned and first-real-run items go to a new ROADMAP section "Before v0.1.0".
- **P67 (front page).** A request for the front page's own permalink (path match, any `?cpage=N` kept) answers `301` to `/` (plus `?cpage=N`); `/` never redirects; children of the front page keep their paths; previews unaffected. The sitemap and `SiteReader::tree` name the front page `/`. The head canonical of `/` is `/`.
- **P68 (restore exits).** `restore` whose final config/store check fails after the folder is in place exits **2** with "restored, but could not check: …". `--force` (or an absent target) with an absolute `[media] root` inside the folder being replaced is refused before anything moves.
- **P69 (restored jobs).** `restore` marks copied `site.backup` rows that are `running` as `done` (they are the snapshot's own run); other rows are left to lease reclaim. `import-site` needs nothing (`jobs` is not in export archives).
- **P70 (startup guard).** Opening a SQLite store refuses when `ferrite.db` is missing and a `ferrite.db.restore-*.tmp` exists (names the file and the `mv` that recovers it); with `ferrite.db` present a leftover tmp only warns.
- **P71 (self-update config probe).** `self-update --data` runs the new binary's `config check --data` before `migrate status`; a failure refuses the update with its output and the hint to run as the service user with its environment; `--skip-config-check` overrides.
- **P72 (rollback on Postgres).** `rollback --schema` on Postgres refuses while the node registry shows a heartbeat fresher than `STALE_AFTER` (names the nodes); cluster mode with all nodes stopped is allowed.
- **P73 (snapshot check).** `--restore-snapshot` reads the snapshot's applied schema (read-only open) and refuses unless it equals the record's `schema_from`; a gid-only ownership mismatch that cannot be applied is skipped with a warning instead of refusing.
- **P74 (gc exit).** `media gc` exits **2** when the store was refused (another install's marker, unreadable marker, failed claim) or any delete failed; the first pass that only writes the marker stays **0**.
- **P75 (periodic phase).** `Periodic` gains an `offset`; `artifacts.gc` runs daily at 03:00 UTC; `site.backup` keeps 00:00. The unique key is unchanged.
- **P76 (sitemap reads).** One new `ContentRepo` method on both backends returns, for a kind, each sitemap file's start cursor `(published_at, id)` and `max(updated_at)` (window function); the index uses it with `sitemap_files`; a kind file seeks to its cursor and walks only its own rows.
- **P77 (consistency).** Blank `q` means "no filter" on every list endpoint; a failed site-title read in core mail falls back to the configured title (one helper); an item the actor cannot read counts as missing in `check_relations`; WordPress import sources must be `http(s)` URLs.
- **P78 (Markdown limits).** Total source bytes capped at 256 MiB (`too-large` problem, run aborts with exit 1 naming the cap); only folders that hold a page count toward the 5000-folder limit; a separate cap of 50 000 visited folders aborts with a message naming it.
- **P79 (zip NFC).** Entries whose names collide after NFC are ambiguous: none of them is read; each is reported as missing media with the reason.
- **P80 (expired lease).** An import run's owner job counts as live only while `status = 'running'` and its lease has not expired, in both store queries and `job_may_start`.
- **P81 (stale rows).** The palette's stale rows keep full colour; staleness is shown by `aria-busy` and a non-colour cue (the existing spinner in the input plus the rows' cursor/opacity removed).
- **P82 (argon2 in tests).** `[profile.dev.package.argon2]` and `[profile.test.package.argon2]` `opt-level = 3`.
- **P83 (archives).** Release archives are reproducible: normalised modes and mtime (1970-01-01 UTC), a sorted file list, ustar, owner 0, `gzip -n -9`; GNU and bsd tar branches.
- **P84 (plugin unit tests in CI).** CI runs `cargo test --manifest-path plugins/Cargo.toml` on the host target for the shipped example crates.
