# M6 rulings

Controller rulings on the M6 designs (13–18) and plans. A ruling wins over the design doc
it names; the doc is updated to match when the part is implemented.

## Design rulings (2026-11-02)

- **P1 (M6-5, 17):** D1–D18 accepted as written: change sets keyed by grant or personal
  token over MCP with a 30-minute gap / 500-change close (D5); REST writes never recorded;
  a failed capture fails the write (D4); no MCP revert tool, read-only `changes_list` (D14);
  90-day retention in `mcp.change_sets_days` (D17); zstd snapshots (D10).
- **P2 (M6-6, 18):** D1–D16 accepted. Scopes `webhooks:read` / `webhooks:write` and the
  `manage_webhooks` capability go after `system` in the enums; M6-2 adds no scopes (if a
  later part adds one, it goes after the webhook ones). `release.*` and
  `change_set.reverted` and `health.completed` are the wave-B event names.
- **P3 (M6-4, 16), changes D2:** an image with `alt: ""` and no `decorative` flag is a
  **warning** (`image-alt-empty`: "mark it decorative or describe it"), not an error, so
  existing sites and imports do not start failing the publish gate. An image with no `alt`
  attribute at all is an error (`image-alt-missing`). `decorative: true` clears both.
  The editor's "decorative" toggle writes `decorative: true` with `alt: ""` from M6-4 on.
- **P4 (M6-4):** D4–D19 otherwise accepted. Releases (M6-3) call `quality::gate::check`
  for every item they publish (D8); the gate's result for a release is all-or-nothing.
- **P5 (M6-2, 14):** D1–D19 accepted, except **D18**: the daily registry check is **off**
  by default (a site makes no outbound request it was not configured for, as with
  `self-update --check`); the Plugins screen has a "Check for updates" action that fetches
  on demand, and `[plugins] registry_check = "daily"` turns the periodic job on. The keys
  (official publisher key, registry index key) are the user's to create, like the release
  key; until then `registry.pub` holds a placeholder that verifies nothing, the publish
  steps in CI are skipped when the secrets are absent, and all tests use throwaway keys.
  The content-meta gap (`plugin.<name>.*` not erased) goes to Later.
- **P6 (M6-1, 13):** D1–D19 accepted, including no content fallback (D8, a missing
  translation is a 404), no redirects on a default-locale change (D12, documented as such),
  the `widens_unique` expand-lint rule (D6) and `site.locales` as `{tag, label}` objects.
  `post.locale` for plugins waits for the next world version. MCP counts across M6: M6-1
  adds `content_translate` and the `translate` prompt, M6-5 adds `changes_list`, M6-4 adds
  `content_check` and `health_report`; each part updates the counts in docs it touches
  and the last to merge reconciles them.
- **P7 (M6-3, 15):** D1–D40 accepted with three changes.
  - **D20 changed:** in a type with a workflow, a user who may approve in that workflow
    (editor or admin) may still edit a published, scheduled or private item in place; the
    save writes an audit row `review.bypassed` and emits no review event. Everyone else
    stages the change in a release, which goes through the workflow. (Fixing a typo on a
    live page must not need a release.)
  - **D16 changed:** the preview iframe is sandboxed without `allow-same-origin`
    (`sandbox="allow-scripts allow-popups allow-forms"`), so theme or plugin output in a
    preview runs in an opaque origin and cannot reach the admin. Previews load through the
    signed preview links (D26), so they need no cookie.
  - **D10 clarified:** the SQLite writer is held per preview request (one page render), not
    for a preview session; the 15 s cap and one-at-a-time limit stay.

## M6-6 execution rulings (2026-11-03)

Recorded in full in [`m6-6-exit.md`](../m6-6-exit.md) §3 (R-M6-6-1 to R-M6-6-14). The ones
another part or the merge must know:

- **R-M6-6-2:** the four webhook tables are appended at the end of the export catalogue
  (`TABLES`), not after `users`; the skipped list gains them at its end.
- **R-M6-6-1:** `0016_webhooks` has a down that is not lossy (as 0011 to 0013).
- **R-M6-6-8:** content events come from the public `ContentService::create` and
  `transition` wrappers, `update_in` and `delete_in`, not from `create_in` /
  `transition_item`, so `seed demo` and uploads emit no content events. A part that adds a
  write path calls `webhooks::emit_content` (or `emit`) in its `Tx`.
- Scope order (P2) as built: `Area::Webhooks` after `System` (24 scope names), capability
  `ManageWebhooks` last in `Capability::ALL`; neither scope is in `Scopes::OAUTH`. A later
  scope goes after `webhooks:write`.
- The MCP site overview's caller scope count is 24 (`mcp.rs` test); the tool count is
  unchanged (no MCP webhook tools, D11).
