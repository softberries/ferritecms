# M3 WordPress import — plan and controller rulings

Decisions made while planning and executing the M3 sub-plans (subagent-driven). M3-1:
docs/superpowers/plans/2026-10-28-m3-1-wordpress-import-core.md (18 tasks). Format: ruling —
reason — cost if wrong. P = plan rulings (full text in the plan), R = controller rulings during
execution. Where the code differs from a ruling's text, the line says "as built".

## M3-1 plan rulings

- P1: the import writes through a new core API (`ferrite-core::import`, `ImportService`/`ImportBatch`), checked once with `Capability::Import` — the public services commit per call and cannot set dates, author, private, meta or comment status — cost: a second write path whose invariants must match the services'.
- P2: M3 is two sub-plans; M3-2 holds the job and API, admin screen, permalink-change redirects (M2a-2b P26), the job-claim EXPLAIN (m15 R17) and the M3 exit — cost: CLI-only import until M3-2.
- P3: idempotency in a persistent `import_map(source, kind, wp_id → ferrite_id, hash, version)`; `import.wp.id` meta is written, never read — the temp IR alone cannot dedupe a re-run from a fresh upload — cost: rows outliving deleted items (treated as unmapped).
- P4: re-run: same hash skip; changed hash and unedited update; edited locally keep and report; gone recreate — cost: local edits block later WP fixes for that item.
- P5: fence = run token checked by an `UPDATE import_runs … WHERE token AND running` first in every batch tx; 120 s stale heartbeat; takeover only on request; `LOCK_IMPORT` best-effort — the advisory lock is not a fence (m15 R17) — cost: one UPDATE per batch.
- P6: batches of ≤500 items, one invalidate event per batch (`[all]` past 1 000 keys), revisions and search written, no plugin actions — R2 (NOTIFY serialises commits) — cost: plugins never see imported items as saved.
- P7: status and date mapping (future in the past → published and reported; GMT dates, local as UTC when GMT is zero) — cost: offset shift on sites without GMT dates.
- P8: WP slugs kept exactly where core allows, else `-N` and reported.
- P9: users matched by e-mail, then login, else created without password, `must_reset`, role author (WXR has no roles, verified) — cost: everyone is an author until changed.
- P10: SEO gains `seo.canonical` and `seo.robots`; Yoast and Rank Math keys verified in plugin source and real exports 2026-10-28; title variables substituted (`sep` = `-`) — cost: per-type title templates are not in WXR.
- P11: block tree gains an `embed` node (YouTube, Vimeo; privacy-mode iframes) and an image `caption`; layout blocks flattened; unsupported marks dropped and counted — cost: lost layout.
- P12: unknown blocks → `html` node (dropped when empty), unknown shortcodes stay text; both counted with examples — cost: preview-only html blocks in the editor.
- P13: media from `--uploads`, or `--fetch-media` through the SSRF-checked client; same sniffing as uploads; variants by the next `serve` — cost: no srcset until a server ran.
- P14: every attachment URL form (sizes, `-scaled`) rewritten; img → `ferrite:media/<uuid>`, links → public URL; internal links fixed after all content exists.
- P15: synthetic corpus A/B checked in; WordPress theme-test data (GPL-2.0) via `FERRITE_WP_CORPUS` only — cost: CI skips the big files.
- P16: ACF definitions read from the export's `acf-field` items and mapped per the plan's table; others raw `wp.<name>` meta; ACF on built-ins stays meta — cost: manual modelling for built-ins.
- P17: permalinks: WXR has no options (verified); old URL = `<link>`; infer a post structure when all posts fit, then redirect every differing path, attachment pages and tag/category bases — cost: unsupported WP tokens (`%day%`, `%post_id%`) end up as redirects.
- P18: comments to plain text, status mapping, pingbacks skipped, threading kept, `by_account` for mapped users — cost: lost comment formatting.
- P19: menus from `nav_menu_item`, one per `nav_menu` term; no locations (not in WXR).
- P20: channel title and description → `site.title`/`site.description` unless `--no-site-options`.
- P21: IR = temp SQLite under `<data>/import/<run-id>/`, passes recorded, deleted on done.
- P22: XML safety: no DOCTYPE, 64 MiB text cap, UTF-8 checked, streaming.
