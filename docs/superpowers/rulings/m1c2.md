# M1c-2 serving — controller rulings

Decisions made during subagent-driven execution of docs/superpowers/plans/2026-10-22-m1c2-serving.md. Format: ruling — reason — cost if wrong.

- Plan ruling P1: theme distribution via artifacts is M1.5; M1c-2 loads themes from embedded starter themes (`rust-embed`) and `data/themes/<name>/` folders; the `themes` table records the active theme name, default `blog` — keeps M1 small — cost: no theme install path until M1.5/M2.
- Plan ruling P2: MiniJinja is synchronous, so all template data is preloaded before rendering; only `related()`/`query()` reach the store (as built, `menu()`/`image()` too), through a `HelperBridge` using `Handle::block_on` on the blocking render thread, capped at 20 calls per render, published-only, recording dependency keys — no async in templates — cost: one blocking thread per render.
- Plan ruling P3: plugins load at startup from the `plugins` table + MediaStore artifacts (enabled rows only) with a store-backed `HostServices` (published-only `content.read`); hot reload on `plugins.changed` is M1.5; install CLI/API is M2, tests write rows + artifacts directly — cost: plugin changes need a restart.
- Plan ruling P4: Task 8 split into 8a (app, render pipeline, bridge, content handlers, cache, errors, headers, health) and 8b (`/_media`, `/_theme`, feeds, sitemap, robots) — size — cost: none.
- Ruling R1: the descendant walk traverses all non-trash descendants (so published grandchildren under a draft page are reached) but records redirects only for published ones — cost: slightly larger walk.
- Ruling R2: the descendant walk runs whenever a hierarchical item's slug/parent changes, regardless of the root's status; redirects only for published descendants; the cap counts walked nodes — cost: walk on draft renames.
- Ruling R3: top-level slugs can't equal content type names; types whose structures share `/%slug%/` at the root (posts default + top-level pages) share a slug namespace (peer slugs count as taken → `-N`); router page-before-post precedence as safety net — cost if wrong: "about-2" surprises.
- Ruling R4: `%year%`/`%month%` use UTC by design (URLs must not move when `site.timezone` changes) — cost: dates near midnight differ from local.
- Ruling R5: the listing store-call bound is 7 (constant in item count) — the media status check is worth one call — cost: none.
- Ruling R6: public paging skips at most 5000 rows; deeper pages → `None` (404) — DoS bound — cost: very deep archive pages unreachable (sitemaps still list all items).
- Ruling R7: author/term archives and term feeds with zero public items → `None` (same as unknown) — no enumeration of logins or embargoed tag names — cost: empty categories 404.
- Ruling R8: `PageItem` exposes a narrow `PublicItem` view (no body/body_html/version/scheduled_at; fields filtered to public media refs) — templates never see a raw `ContentItem` — cost: themes needing more fields need a facade change.
- Ruling R9: search caps at 200 matches; the status filter keeps ids only, then one `get_many` for the page — bounds anonymous search cost — cost: totals for broad queries cap at 200.
- Ruling R10: option writes under `permalink.*` also emit `all` — every URL changes — cost: full cache flush on a permalink change (rare).
- Ruling R11: media row writes emit `post:<media id>` in the same Tx (or a documented emitter obligation where no write path exists yet) — cost: none.
- Ruling R12: term writes emit `term:<id>` + `archive:<types>` only (no per-item expansion or `all` fallback); hydrate records term keys for every term shown — cost: consumers bypassing hydrate must record term keys.
- Ruling R13: top-level slugs equal to taxonomy names, `author`, `page`, `search`, or matching `^[0-9]{4}$` are reserved (same mechanism as type names); structure literals must be lowercase — static routes win, so these must not be content — cost: pages titled "2024" get "2024-2".
- Ruling R14: template memory blow-up via string doubling is accepted for M1c-2 — themes are admin-installed (admin trust, unlike plugins); fuel bounds steps; documented; revisit in M1.5 when third-party theme artifacts install (per-thread counting allocator or render worker) — cost: an admin-installed hostile theme can OOM the process.
- Ruling R15: auto-escape everything except `.txt`/`.css`/`.js` templates — fail safe — cost: none.
- Ruling R16: embedded `themes/` holds starter themes only; test fixtures live under `crates/ferrite-theme/tests/fixtures` — cost: none.
- Ruling R17: a static front page uses `front-page.html` → the full Page row → `index.html`; a posts front page uses `front-page.html` → `home.html` → `index.html` — consistent with `/about/` — cost: none.
- Ruling R18: render-filter deadline default 200 ms (hard 1.5x), configurable as `plugins.render_deadline_ms` — the epoch deadline includes host-import await time and Postgres debug-build imports take ~80 ms — cost: slow plugins hold a request longer (still bounded).
- Ruling R19: a failed/invalid plugin call marks the page volatile (TTL ≤ volatile TTL) — a transient failure must not stay cached — cost: none.
- Ruling R20: `meta.set` is refused during render-class filter calls; writes only in actions/routes — cost: plugins wanting lazy meta writes must use actions.
- Ruling R21: a non-null `plugins.granted` must be a superset of the manifest capabilities or the plugin is skipped; null = manifest honoured (P3) — cost: none.
- Ruling R22: the sanitiser allows `a[target]` and `code[class=language-*]`; non-raw outputs are always re-sanitised — cost: none.
- Ruling R23 (superseded by R24): skipping a gap after 5 s flushes the whole cache — a late-committing writer must not leave stale pages — cost: rare full flush.
- Ruling R24: a gap skip flushes AND keeps the skipped seq in a late set probed each tick for 10 min; late arrivals are applied — cost: one extra `since()` per tick while the late set is non-empty.
- Ruling R25: the cache key host is the configured site host (`site.url`), not the `Host` header — no cache fill via arbitrary Host — cost: multi-host sites need M2 config.
- Ruling R26: the 404 body is rendered once per (theme, deps) and cached under a fixed internal key (status 404, deps recorded); the 404 template does not receive the request path — random-URL requests cost one redirect lookup + route only — cost: themes can't echo the missing path.
- Ruling R27: empty date archives 404 (as R7) — no cache fill by year enumeration — cost: none.
- Ruling R28: render concurrency semaphore (default 2×cores), 5 s wait then 503 `Retry-After` — protects the blocking pool — cost: 503s under extreme load.
- Ruling R29: `media_variants(hash, item_id, name)` table + hash index (expand migration `0003_media_variants`, backfilled); artifacts primary-key precheck — anonymous random-hash `/_media` requests must be O(index) — cost: one more table to maintain.
- Ruling R30: archive pages get an `archive` context object (kind, term, author, year, month) and `pagination` (page, pages, prev_url, next_url) built by `ferrite-http`; MiniJinja's `urlencode` filter enabled — themes must not parse URLs — cost: cross-crate change (core `Listing`, theme `RenderContext`, http).
- Ruling R31: only `X-Forwarded-For` (from trusted peers, right-most untrusted hop) is honoured, for `client_ip` logging; `X-Forwarded-Proto`/`Host` are ignored since URLs come from `site.url` and the cache host is pinned — cost: TLS-terminating proxies can't change the scheme (not needed in M1).
- Ruling R32: render slot covers the whole pipeline (data load + plugin filters + render) — bounds plugin concurrency — cost: slot held longer
- Ruling R33: search query capped at 200 chars (longer → truncated to 200 on a char boundary, canonical) — bounds cached page size — cost: none
