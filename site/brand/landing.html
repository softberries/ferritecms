Connect your assistant to your site and ask: it writes and publishes posts, organises media and menus, moderates comments and checks the site's health. It works as you, within the permissions you approve, and its changes are recorded in the audit log under the app's name. FerriteCMS is a WordPress-style CMS in one Rust binary, with every plugin in a WebAssembly sandbox.

Four commands to a running site

$ ferrite init --data mysite --url http://localhost:8080
$ ferrite seed demo --data mysite --profile business
$ ferrite user create --data mysite --login me --email me@example.com
$ ferrite serve --data mysite
Listening on http://127.0.0.1:8080

AI assistants, over MCP

Run your site from your AI assistant

Every site serves a Model Context Protocol endpoint. Paste one address into your assistant, sign in to your site, approve what it may do, and ask.

Coming in the next release (0.2.0); build from source today.

The address to paste https://your-site/mcp
  • Claude
  • ChatGPT
  • Claude Code
  • Cursor
  • VS Code
  • any MCP client

Claude and ChatGPT connect from their own servers, so they need your site on public HTTPS. Claude Code, Cursor and VS Code also work with a site on localhost:

$ claude mcp add --transport http ferrite http://localhost:8080/mcp
  • Your login. The assistant signs in through your site's own sign-in and consent screen. No passwords or keys to copy.
  • Your role. It can do only what you can, in the areas you approve: read only, or write to content but not settings.
  • Audited. Its changes are recorded in the audit log under the app's name. Disconnect it at any time, or turn assistants off for the whole site.

Why FerriteCMS

Familiar to WordPress users.
Built like modern infrastructure.

Managed by AI

Connect Claude, ChatGPT, Claude Code, Cursor or VS Code over MCP. 56 tools write, publish and schedule content, upload media and set alt text, edit menus, terms and redirects, moderate comments, change settings and check the site's health, as you and within the permissions you approve. Installing plugins, managing users and backups stay with people.

One binary, one data folder

The web server, REST API, admin, starter themes and plugin runtime are compiled into one program. A site is a folder: SQLite plus its media.

Plugins in a sandbox

Plugins are WebAssembly components with no SQL, file system or network access unless declared. Every call has memory, fuel and time limits.

Themes without code

Templates, a template hierarchy and a fixed set of safe helpers. Blog, docs and business starter themes are built in; this site uses the docs theme.

Moves from WordPress

Import a WXR export with its posts, pages, media, users, terms, comments and menus, plus redirects from the old permalinks.

A keyboard-first admin

A block editor with autosave, revisions and previews, a ⌘K command palette, a media library, menus, content types and custom fields.

Operations built in

Backups and restore, signed self-update and rollback, HTTPS through ACME, Prometheus metrics and a ferrite doctor check.
